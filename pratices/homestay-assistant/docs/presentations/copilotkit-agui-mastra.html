CopilotKit + AG-UI + Mastra

Three layers for agentic apps: UI, protocol, and agent brain.

CopilotKit AG-UI Mastra

Context

Text chat alone is not a product

Real apps need streaming UX, tools, confirmations, and page sync — without inventing a custom agent↔UI protocol.

  • Users expect UI actions, not walls of text
  • Agents must call tools and return grounded answers
  • Frontend and agent need a shared, inspectable contract

Overview

Split the job into three layers

Agent

CopilotKit

What it is

The frontend + runtime layer for copilots inside your application.

  • React components and hooks (CopilotChat, tool hooks)
  • App-server runtime (e.g. Next.js /api/copilotkit)
  • Brokers auth, runs, and streaming events to the UI

AG-UI

What it is

An open, event-driven protocol between user-facing apps and AI agents.

  • Standard events: text, tools, state, run lifecycle
  • Bidirectional: user input, agent output, pauses for humans
  • Framework-agnostic: Mastra today, another agent tomorrow

Mastra

What it is

The agent framework: LLM reasoning, tools, and conversation memory.

  • Agents with instructions and tool registries
  • Structured tool calling (e.g. Zod-defined tools)
  • Threads / working memory for multi-turn chats

Connection

How they fit together

CopilotKit speaks AG-UI. Mastra plugs in through an AG-UI adapter.

  • CopilotKit — UI + runtime you ship
  • AG-UI — the wire format between them
  • Mastra — agent adapted via @ag-ui/mastra
